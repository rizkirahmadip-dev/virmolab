Installation

VirmoLab runs on 64-bit Windows 10/11 with no need for Python, WSL, MGLTools, or any other program. The Vina and AutoDock-GPU docking engines are bundled. The advanced tools that exist only for Linux (Uni-Dock, OpenFE, GNINA, Boltz-2) are optional and install from inside the application; see Advanced tools.

Option A — Installer (recommended)

  1. Run VirmoLab-Setup-x.y.z.exe. If Windows SmartScreen appears (“Windows protected your PC”), click More info › Run anyway — the installer is not yet signed with a paid certificate.
  2. Choose who VirmoLab is installed for. The default is this user only, in %LOCALAPPDATA%\Programs\VirmoLab, with no administrator rights. Choose all users for C:\Program Files\VirmoLab (administrator rights needed).
  3. Choose the optional tasks: desktop icon, and associating .pdbqt/.vmdbackup files with VirmoLab.
  4. Click Install, then Finish to open VirmoLab.

Uninstall through Settings › Apps › VirmoLab › Uninstall. Projects in the working folder (Documents\VirmoLab by default) are not removed.

Option B — Portable build (no installation)

  1. Extract VirmoLab-Portable-x.y.z.zip into any folder (a USB stick, or D:\VirmoLab). Avoid protected folders such as C:\Program Files.
  2. Run VirmoLab.exe.

The portable build keeps its settings in data\pengaturan.ini and its default projects in Proyek\ inside that same folder — it never touches the registry. The portable marker is the file portable.flag; do not delete it.

First launch

  1. System check: GPU, driver, CPU, RAM, and the default docking mode (GPU when OpenCL is available, CPU otherwise). If a GPU is present but OpenCL is not, follow the driver guidance shown — see GPU setup.
  2. Companion software: PyMOL, ChimeraX, and Discovery Studio Visualizer are detected for the “Open in…” button. All of them are optional.
  3. Working folder: where new projects are stored.

GPU detection runs again every time VirmoLab starts, so nothing needs configuring after moving to another laptop or updating a driver. The wizard can be reopened from Tools › Check system and GPU….

Updating

VirmoLab checks GitHub for a new release at most once a day, a few seconds after the application starts. When a new version exists, the update dialog opens by itself — once per version number, not every time the application runs. The same dialog is always available from Help › Check for updates….

  1. Press Download and install. The installer is downloaded to %LOCALAPPDATA%\VirmoLab\unduhan; an interrupted download resumes rather than starting over, and can be cancelled at any time.
  2. The file's SHA-256 fingerprint is checked against the SHA256SUMS file from the same release. A file that does not match is rejected and deleted at once, and is never run.
  3. VirmoLab closes, the update installs without asking anything, and the application opens again by itself. Any work in progress is asked about first, before the application closes.

Projects, settings, and WSL tools are preserved; the new version is installed in the same folder as the previous one, including a folder you chose yourself. The SmartScreen warning does not appear for an in-app update — only for an installer you download yourself through a browser.

The automatic check can be turned off under Tools › Settings. An update is never downloaded or installed without you pressing the button.

The portable build has no installer: download the new release's zip from the releases page and replace the folder's contents. Do not overwrite the data\ and Proyek\ folders.

Advanced tools (optional, through WSL)

Four tools exist only for Linux and are therefore not part of the installer. The core features (preparation, docking with Vina and AutoDock-GPU, analysis, reporting) do not need them. When you do need them, install them from inside VirmoLab through Tools › Install advanced tools (WSL)…. They are installed into WSL (Windows Subsystem for Linux), in the Linux home folder ~/virmolab-alat; no project data is sent anywhere.

Prerequisites

The dialog checks all of these before the Install button becomes active, and offers a fix for whatever is missing.

  • Windows 10 version 2004 (build 19041) or newer, or Windows 11.
  • WSL 2 with a Linux distribution (Ubuntu). If there is none, the Install WSL… button opens the Windows administrator consent dialog. After that, restart, open Ubuntu once from the Start menu to create a username and password, then reopen the dialog.
  • An NVIDIA GPU with an up-to-date Windows driver for Uni-Dock and GNINA (both are CUDA-only). Without an NVIDIA GPU those two are skipped; OpenFE and Boltz-2 still install and run on the CPU, but very slowly.
  • Disk space on the Windows drive holding the WSL virtual disk (usually C:). That virtual disk grows on its own and does not shrink automatically after files are deleted.
  • Internet access to conda-forge, GitHub, PyPI, PyTorch, and Hugging Face. On a campus network a proxy may be needed (the HTTPS_PROXY variable inside Ubuntu).

Installing

  1. Open Tools › Install advanced tools (WSL)… and wait for the prerequisite check (a few seconds).
  2. Click Install on the package you need. The step in progress, its elapsed time, and the log appear under Progress; the dialog must stay open.
  3. When it finishes, the feature buttons become active immediately, without restarting VirmoLab.

Stop halts every installer process inside WSL. Downloads that already finished are kept, so clicking Install again resumes — including after a dropped connection. The full log for each package is in %LOCALAPPDATA%\VirmoLab\log\alat_wsl_gpu_rbfe.log and alat_wsl_cofolding.log.

If the computer has more than one distribution, choose which one under Prerequisites; VirmoLab uses that distribution for every advanced tool.

Removing

In an Ubuntu terminal: rm -rf ~/virmolab-alat ~/.boltz. The space on drive C: only returns once the WSL virtual disk is compacted, for example with wsl --manage Ubuntu --set-sparse true in PowerShell (WSL 2.0 and later).

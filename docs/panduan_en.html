Workspaces

Three workspaces decide which tabs and panels are shown so the screen stays uncluttered: Prepare (Ctrl+1, steps 1–3), Docking (Ctrl+2, step 4 plus the Results tab), Analysis (Ctrl+3, every tab plus the Interactions panel). The workspace follows the step automatically, and the step follows the workspace.

Panels can be moved, stacked, or detached; the layout is saved by itself. Restore it with View › Reset layout. A panel you closed comes back from View › Panels. Dark mode: Ctrl+T.

The welcome page

Choose Fetch protein from RCSB, Open file (or drag a file onto the window), Open project, or Recent project. The links below open the tutorial PDF and this guide.

Step 1 · Protein

  1. Load a protein: Fetch from RCSB PDB… in the work panel (Ctrl+Shift+P, type 1HSG for instance), Fetch from AlphaFold DB… (see below), or Open file… (Ctrl+O: PDB, PDBQT, mmCIF, SDF, MOL2, SMILES). The structure is split automatically into protein, native ligand, water, and ions.
  2. Click the blue Prepare receptor… button (Ctrl+Shift+1).
  • Choose the protein and its chains; remove water, remove the native ligand and additives, keep metal ions (Zn, Mg, Ca, Mn, Fe, Cu, Co, Ni) within a radius of the native ligand (0 = all of them).
  • Alternate conformations: highest occupancy (recommended) or always altloc A. Charges: Gasteiger computed by Meeko (recommended) or residue template charges.
  • The result is an object named “… (ready)”; the files reseptor/reseptor.pdbqt and laporan_prep.txt are saved in the project. Residues with incomplete atoms are dropped and reported; if Meeko fails, Open Babel is used automatically.

Proteins from AlphaFold DB

For targets that have no crystal structure yet. Type a UniProt code (P00918, say) or a protein or gene name (ACE2), choose the organism, click Search, pick one result, then Import.

  • The protein is coloured by pLDDT (per-residue confidence): dark blue > 90, light blue 70–90, yellow 50–70, orange < 50. A pLDDT summary appears in Properties and in the Messages panel; this colouring is also available under View › colour pLDDT (AlphaFold).
  • Disordered N and C termini (pLDDT < 50) are trimmed by default, because they can cover the pocket. The threshold can be changed, applied anywhere, or switched off.
  • P2Rank pocket detection runs automatically with the alphafold configuration. Once the grid box is set, VirmoLab reports the pLDDT of the residues inside the box and warns when it is low.
  • An AlphaFold model holds no ligand, cofactor, or ion, and pocket side chains can differ from the bound form. Validate against a reference ligand where one exists, consider flexible residues, and state the model entry and version in your methods (the report does this for you).

Step 2 · Ligands

The work panel offers Fetch from PubChem… (Ctrl+Shift+L, one name or CID per line), From SMILES…, and Open file / folder…. Then click Prepare ligands… (Ctrl+Shift+2).

  • Options: protonation at a given pH (7.4 by default) with Open Babel or Dimorphite-DL, MMFF94 minimisation, rigid or flexible macrocycles.
  • Dimorphite-DL works from per-group pKa rules. variants ≤ 1 gives one state at exactly that pH; variants ≤ 2–8 gives every protonation state within pH ± 1, each becoming a separate ligand named name [v1], [v2], and so on, so they can all be docked and compared. A caveat: Dimorphite-DL tends to treat phenols and catechols as deprotonated; for flavonoids, Open Babel is usually more reasonable. Check the charge column.
  • Status: ready, warning (more than 32 torsions or 256 atoms, say — not possible with AutoDock-GPU, use Vina), failed (with the reason). One ligand failing does not stop the others.
  • Prepared ligands join the Ligands ready for docking group in the Objects panel.

Step 3 · Docking area (grid box)

  • If the structure holds a native ligand, the box is centred on it automatically (crystallisation additives such as GOL, EDO, and SO4 are ignored).
  • Buttons: Centre on native ligand (recommended), Centre on selected residues (click an atom or pick residues in Objects, Ctrl+click for several), Fit to selected ligand, Detect pockets (P2Rank)…, Whole protein (blind docking). All of them are in the Prepare menu as well.
  • Detect pockets (P2Rank): for proteins with no native ligand — an AlphaFold model or an apo structure. P2Rank, a machine-learning method, finds binding pockets in 5–30 seconds; pockets are marked with numbered orange spheres in the viewport and listed in a table (score, probability, residues). Pick one and choose Use this pocket: the box is centred on the pocket, and its size is the spread of the pocket residues plus 4 Å (16–30 Å). On 1HSG, pocket #1 lies 0.8 Å from the centre of the crystallographic indinavir.
  • Flexible residues… (Prepare menu, or Configure… in step 4): tick 2–6 pocket side chains that may rotate during docking (candidates are ordered by distance to the native ligand; Gly, Ala, and Pro are not offered; 8 at most). Pick the 6 nearest ticks the six closest side chains in one go (a practical limit: every side chain adds 1–4 torsions to the search space), and Clear unticks everything. It works with AutoDock-GPU and Vina, not with AutoDock4. The side chains of each pose appear as an object named Pose n · flexible residues, and interactions are computed from those positions. A ΔG obtained with flexible residues is not directly comparable with rigid docking — compare ligands within the same setting. Back to rigid receptor turns it off; preparing the receptor again does so too.
  • Covalent docking… (Prepare menu, or Configure… in step 4): choose one nucleophilic residue (Cys, Ser, or Lys) whose nucleophilic atom lies inside the grid box. Ligands carrying a reactive group (a warhead) are bonded chemically to that residue's side chain, then docked as a single residue–ligand adduct with the tethered method (AutoDock-GPU --flexres; the receptor is used without the target residue's side chain). The reactive groups recognised are: Michael acceptors (acrylamides, enones, vinyl sulfones), activated alkynes, α-haloketones and haloacetamides, sulfonyl fluorides, nitriles, and aldehydes — which of them fit depends on the residue, and the dialog shows what was detected per ligand. Ligands with no matching reactive group are skipped. The score reported is the adduct–receptor energy, not a binding ΔG: Ki and ligand efficiency are not shown, and scores are comparable only between covalent ligands on the same target residue. AutoDock-GPU only; it cannot be combined with flexible residues. Turn off (ordinary docking) restores it; preparing the receptor again does so too.
  • Margin around the ligand (Å): the extra distance on each side of the ligand that the top two buttons use, 8 Å by default. This is the number that most often needs adjusting: a shallow, enclosed pocket is fine with 4–5 Å, while a flexible ligand or a branched pocket needs more room. Too narrow and poses are clipped at the box edge; too wide and the search slows down without becoming any more accurate. The button labels show the value currently in force.
  • Size and position: centre X/Y/Z, the size of each axis, the grid spacing, and the number of grid points. Below them are the box bounds (the minimum–maximum range of each axis) and the volume — the bounds for matching the box to the pocket you can see in the viewport, the volume for judging how long the search will take. A warning appears above 126 points per axis or 30 Å.
  • Keep all three sides equal: while this is ticked, changing one side changes the other two with it, so the box stays a cube. Useful for blind docking and for comparing several targets with boxes of the same size.
  • Grid spacing sets how densely the points are placed: denser means more accurate and slower. AutoDock's standard value is 0.375 Å; raising it is the easiest way past the 126-point warning without shrinking the box.
  • Every change to the box enters the Ctrl+Z history, so experimenting with sizes is safe: the previous box can always be brought back.
  • With the mouse in the viewport: Shift+drag moves the box; Shift+scroll resizes it; Alt+scroll resizes one axis (choose it with X/Y/Z). G shows or hides the box.

  • Accuracy: Fast, Standard, or Thorough (or a preset of your own) — applied immediately.
  • Advanced ▸ opens the detailed parameters (number of runs, evaluations, exhaustiveness, number of poses, energy range, CPU threads, seed) and the button that saves a preset. A fixed seed means the result can be repeated. The same settings window: Docking › Docking settings… (Ctrl+D).
  • Device: if the laptop has more than one OpenCL GPU (Intel plus NVIDIA, for instance), all of them appear; the one with the most VRAM is chosen by default.
  • Click Run docking (n ligands) or press F5. Every prepared ligand is docked; to dock only some, select them in the Objects panel first.

The job queue

  • The Queue panel (the Queue: … ▴ button in the status bar, or Ctrl+J) shows the status, progress, best ΔG, elapsed time, and estimated time remaining for each ligand. The panel closes itself once every job has succeeded.
  • Pause (after the ligand currently running), Resume, Cancel — in the panel or the Docking menu. The window may be minimised; a Windows notification appears when the run finishes.
  • If the GPU fails with an OpenCL error, the job continues automatically with Vina on the CPU; the reason is written into the Messages panel.
  • Closing the application while docking: jobs become Paused and can be resumed without repeating the ligands that already finished.

Step 5 · Results

  • Default columns: #, Ligand, ΔG (kcal/mol), LE (ligand efficiency), RMSD crystal (green at ≤ 2 Å), PoseBusters, H (hydrogen bonds). Right-click a column header to show the others: estimated Ki, cluster, reference RMSD, hydrophobic, π, other interactions, engine, job.
  • Sort by clicking a header; filter by name or a ΔG limit. Select a row to load its pose into the viewport; double-click still works too.
  • Menu: Analysis › Results table (Ctrl+R).

3D interactions

The Interactions tab (on the right, in the Analysis workspace) lists interactions by type with their distances and angles; click a row to focus that residue. Tick the types you want shown; there are options for distance labels, residue labels, and residues as sticks. I shows or hides the interactions. Colours: hydrogen bond, hydrophobic, π–π, π–cation, salt bridge, halogen bond, metal. The criteria: Methods & criteria.

Per-atom energy contribution

Analysis › Per-atom energy contribution (K) colours the atoms of the active pose: green favourable, red unfavourable; the larger the sphere, the larger the contribution. It is computed from the intermolecular terms of the AutoDock Vina scoring function (gauss, repulsion, hydrophobic, hydrogen bond) per ligand atom; the total comes close to Vina's “Final Intermolecular Energy”. Useful for seeing which part of a molecule is worth modifying.

Pinning a pose

Opening another pose normally hides the previous one. Right-click a pose in the Objects panel › Pin to keep it visible (a pin icon) — for comparing the best poses of two ligands in one viewport, for instance.

2D interaction diagram

To look at another compound there is no need to go back to the results table: the Ligand: box in this tab's top bar moves between compounds, ordered from the best ΔG.

Save as SVG or PDF (vector, editable in Inkscape, Illustrator, or Word) or as PNG/TIFF at a DPI of your choosing. The Copy button puts the image on the clipboard to paste straight into Word or PowerPoint.

Redocking validation

Docking › Redocking validation… (also in the Analysis menu) redocks the crystal ligand with the same parameters, starting from the crystal conformation without minimisation, then computes the RMSD of the best pose against the crystal. RMSD ≤ 2.0 Å means the method is valid. The result is stored in the project and quoted in the PDF report. Do this before interpreting any screening results.

Pose checking (PoseBusters)

Every best pose is checked automatically with PoseBusters (22 tests: bond geometry and angles, ring planarity, stereochemistry, internal energy, minimum distance to the protein, and so on). The outcome appears in the PoseBusters column of the Results tab — hover to see which tests failed — and in the pose Properties. Analysis › Check active pose (PoseBusters)… shows every test for any pose.

Comparing ligands & the interaction map

Side-by-side viewports (with a Sync viewpoints button), a list of residues that interact with every ligand, and a residue × ligand heat map. Analysis › Residue × ligand interaction map shows the map for all results.

Interaction fingerprints (IFP): each best pose is summarised as a set of “residue × interaction type” (van der Waals excluded). The IFP vs crystal column in the Results tab is the Tanimoto similarity to the crystal pose of the native ligand (1 means an identical interaction pattern; useful for picking ligands that mimic the native one). Statistics tab › Interaction similarity (IFP) shows the ligand-to-ligand similarity matrix; the Excel export holds an Interaction fingerprints sheet (0/1 per residue × type).

Consensus scoring

Analysis › Consensus scoring… combines several scoring functions so that the ligand ranking does not rest on one engine alone. Tick the score columns: jobs run with different engines (AutoDock-GPU and Vina, say) and/or rescoring of the best poses with the Vina and Vinardo scoring functions (fast, without redocking; the results are stored in the project). The table shows ΔG and the rank for each column, the mean rank (the consensus order), the mean z-score, and a ✓ for ligands that stay consistently in the top percentile (20 % by default) across every column. Agreement between scoring functions is judged with Kendall's W (≥ 0.7 strong; < 0.5 weak — interpret with care) and Spearman correlation. CSV export and a ready-to-paste methods paragraph are provided.

Ligand properties & BOILED-Egg

Analysis › Ligand properties and BOILED-Egg: MW, WLOGP, TPSA, donors and acceptors, rotatable bonds, QED; the Lipinski, Ghose, Veber, Egan, and Muegge rules; PAINS and Brenk alerts; and the BOILED-Egg plot (predicted intestinal absorption and brain penetration). Export as CSV, or the plot as SVG/PDF/PNG/TIFF.

Statistics & plots

Analysis › Statistics and charts: a ΔG histogram, scatter plots with regression and Pearson/Spearman correlation (with p values), a bar chart of the best ΔG values, and a correlation matrix between variables (ΔG, LE, pKi, interactions, ligand properties). Choose one job or “All jobs”. Plots and data can be exported.

Statistical tests & publication plots

The Tests & Plots tab (Analysis › Statistical tests and publication charts) is for your own experimental data, in vitro results for instance. The flow is: data sheet → analysis → plot, each updating by itself when the data change, and all of it stored in the project.

  • Column data: one column per group, rows are replicates. Paste straight from Excel (Ctrl+V; a header row is recognised), import CSV, or use Fill data ▾ › ΔG per job / per engine from the docking results. Double-click a column header to rename it.
  • Automatic test selection checks normality (Shapiro–Wilk) and homogeneity of variance (Brown–Forsythe), then chooses: 2 groups → Welch's t-test / Mann–Whitney (paired: paired t / Wilcoxon); ≥ 3 groups → ANOVA + Tukey, Welch ANOVA + Games–Howell, or Kruskal–Wallis + Dunn (Holm). It can also be chosen by hand, including ANOVA + Dunnett against the first column as control.
  • Results: descriptive statistics (n, mean, SD, SEM, median, range), the test statistic, df, p, effect size (Cohen's d / Hedges' g, η², ε², r), post-hoc tables, a ready-to-paste interpretation paragraph and Methods paragraph (the Copy results & methods paragraph button), and a warning whenever an assumption is not met.
  • Plots: bars with points, points (mean ± SD/SEM/95 % CI), box and whisker (Tukey), points (median ± IQR); automatic stacked significance brackets (ns/*/**/***/**** or exact p); the Okabe–Ito palette (colour-blind friendly), blue, or grey for print.
  • XY dose–response data: the first column is concentration, the following columns are response replicates. Four-parameter nonlinear regression (log[inhibitor] vs response, free slope) gives IC₅₀/EC₅₀ with 95 % CI, the Hill slope, and R²; the x axis is logarithmic.
  • Paired data with ≥ 3 columns (tick Paired; a row is one subject): repeated-measures ANOVA with the Greenhouse–Geisser correction, or Friedman when the data are not normal; post-hoc paired t or Wilcoxon.
  • Multiple-comparison correction can be chosen: Holm (default), Bonferroni, Šidák, or Benjamini–Hochberg (FDR) — used by Dunn, the paired post-hoc tests, and two-way ANOVA.
  • Two-factor data (two-way ANOVA): the first column holds the levels of factor A (repeated for each replicate), the remaining column headers are the levels of factor B. Results: the A, B, and interaction effects (type III sums of squares, η²ₚ), comparisons between A levels within each B level, and a grouped bar chart with a legend.
  • Assumption checks: the descriptive table now carries D'Agostino–Pearson (n ≥ 8) alongside Shapiro–Wilk; choose the Q–Q plot to inspect normality visually; possible outliers are reported with Grubbs' test (and never removed automatically).
  • Dose–response model: Automatic compares 4PL (free slope) against 3PL (Hill = 1) using an extra sum-of-squares F test and AICc, then uses whichever fits better; 4PL or 3PL can also be forced.
  • ROC data: column 1 holds the scores of the negative group (decoys or controls), column 2 those of the positive group (actives or cases). For docking ΔG, choose Low score = positive. Results: AUC with a 95 % CI (DeLong), p, the optimal cut-off (Youden index) with its sensitivity and specificity, enrichment factors EF1%/5%/10%, and BEDROC and logAUC (early enrichment) with bootstrap CIs — made for validating virtual screening of actives against decoys. Choose the view: ROC, semi-log ROC, or an enrichment curve.
  • Contingency data: the first column holds the group names, the following columns the frequency of each category (Improved / Not improved, say). A 2 × 2 table gives Fisher's exact test, χ² with Yates' correction, and the odds ratio and relative risk with 95 % CIs; a larger table gives Pearson's χ² (switching to an exact r × c Fisher test when expected frequencies are small) and Cramér's V. The plot is a 100 % stacked bar chart.
  • Export as SVG/PDF (vector) or PNG/TIFF at 600 dpi, Copy to the clipboard, or send to the ＋ Composer to become a figure panel.

Plot formatting (click an element)

The Format panel on the right (the Format ◂/▸ button) controls how the plot looks. Move the mouse over the plot and whatever can be formatted is highlighted; click it to open it in the panel — the title, the Y axis label, the Y axis (minimum, maximum, tick spacing, log₁₀ scale, and an axis break for skipping an empty range when one group is far larger than the rest), the X axis (label, slanted group names), the groups (colour per group, marker shape and size, opacity, bar width), and the significance marks. Click the plot background for the general settings (size, font, line weight, palette, grid, individual points).

Reference lines & annotations: on the Y axis page fill in Reference lines, for example −8.2=Native ligand; −7 (labelled dashed lines); on Plot (general) fill in Annotation (| starts a new line) and choose its corner.

Saved styles: save a look you like (font, colours, sizes, markers) with Save…, then apply it to another plot with Apply — text and axis ranges are left alone. Three styles come built in: Journal black and white, Journal column (compact), and Presentation (large type).

Figure composer (panels A/B/C)

Analysis › Figure composer (Ctrl+Shift+F) combines several images into one journal figure labelled A, B, C. Add panels from ＋ Add ▾: a Tests & Plots chart, a Statistics chart, a 2D interaction diagram, a BOILED-Egg plot, a 3D viewport image, or an image file (PNG/JPG/SVG). Reorder by dragging or with the ↑ ↓ buttons; tick Full width to give a panel — a 3D image, say — a row of its own.

  • Set the number of columns, the gap between panels, the label style (A / a / (A) / (a) / A.), the label size, and the print width (85 / 120 / 174 mm).
  • Match font scale across plots (on by default) shrinks every plot by the same factor, so type is the same size throughout the figure.
  • Save as vector PDF/SVG or as TIFF/PNG at 600 dpi, or copy to the clipboard. The composer's contents are stored in the project.

MD & MM/GBSA

Analysis › MD & MM/GBSA… refines the best docked poses with OpenMM: Amber ff14SB for the protein, OpenFF Sage 2.3 for the ligand (NAGL charges, equivalent to AM1-BCC), and either OBC2 implicit solvent or explicit TIP3P water. Tick the ligands (the top 5 by default), choose a level, then press Run.

LevelWhat it doesTime (example: RTX 3060 / 8-core CPU, 1 ligand)
LightComplex minimisation + single-point MM/GBSA±20 seconds / ±40 seconds
Medium1–2 ns of implicit-solvent MD + RMSD/RMSF + averaged MM/GBSA±15 minutes / ±7 hours per 2 ns
Full10–100 ns of explicit-water MD + multi-frame MM/GBSA±2.5 hours per 10 ns / not advisable without a GPU
  • The first time the dialog opens, VirmoLab measures how fast your laptop is on your own complex (±30 seconds), then shows an estimated time and a verdict of Recommended (< 2 hours), Possible (long) (2–12 hours), or Not recommended (> 12 hours). The measurement is stored per device; Measure speed repeats it.
  • Pause writes a checkpoint; Resume continues from it at any time, including after the application has been restarted. Closing VirmoLab while MD is running pauses it with a checkpoint. Keep the laptop plugged in for long runs.
  • Full MD trajectory analysis (F2): since VirmoLab 1.2 this presents seven tabs of results:
    • Summary: statistics for the second half (ligand RMSD, Cα RMSD, Rg, hydrogen bonds, MM/GBSA ΔG as mean ± SD), a convergence badge, and a Compute advanced analysis button for older MD trajectories held in saved DCD files.
    • Stability: interactive plots of ligand and protein RMSD, per-residue RMSF, radius of gyration (Rg), and SASA (protein, ligand, and the buried contact area via rdFreeSASA / Shrake–Rupley).
    • Interactions: a table of contact residue occupancy, plus a per-frame binary barcode of interactions and hydrogen bonds (RLE-compressed to save memory).
    • PCA & FEL: projection of the Cα coordinates onto the principal components (PC1 and PC2), and a 2D free energy landscape (Boltzmann FEL, ΔG = −kBT ln(P/Pmax)).
    • Clusters: hierarchical clustering of the ligand conformations (2.0 Å RMSD threshold) with a representative medoid structure for each. There is a Show medoid button for the 3D viewport, and Use as ensemble receptor for multi-conformation docking afterwards.
    • Replicas: multi-replica simulation (1–5 independent replicas with different random seeds; three replicas is the recommendation for publication), with a consistency table and overlaid RMSD curves.
    • Actions & publication: every plot offers Send to composer and Save figure… (vector SVG or raster PNG).
  • Files in the project folder md/<id>/: hasil.json, kompleks_minimisasi.pdb, topologi.pdb plus trajektori_terlarut.dcd (open these in PyMOL, VMD, or ChimeraX), and a folder of medoid PDB clusters.
  • Interpretation: MM/GBSA leaves entropy out, so its numbers come out far more negative than an experimental ΔG; use them to compare ligands on the same receptor with the same settings. A mean ligand RMSD above 3 Å says the pose is unstable. Receptors with metal ions use a nonbonded model, which is an approximation.

Design & advanced analysis tools

The tools below live in the Analysis menu unless stated otherwise. All of them run offline on your own computer. Several are rule-based estimates: each dialog states its assumptions and limits at the bottom — read those before any of the numbers reach a manuscript.

Binding pocket detection (geometric)

VirmoLab's own cavity finder, for apo structures or AlphaFold models with no co-crystallised ligand. Unlike Prepare › Detect pockets (P2Rank), which uses a machine-learning model and needs Java, this one is purely geometric and always available.

  • The structure is wrapped in a 0.8 Å grid. Every point outside the van der Waals surface is examined along 13 axes; an axis blocked by protein in both directions counts as one protein–solvent–protein event (PSP, the LIGSITE approach). Points with PSP ≥ 10 that lie 1.4–5 Å from the wall are taken as part of a pocket, then clustered.
  • Water, ions, and crystallisation solvents (HOH, SO4, GOL, EDO, DMS, …) are ignored. A co-crystallised ligand is not ignored: while it is still in place its pocket looks filled — remove it first (the receptor wizard already does) so the cavity is found.
  • The Suitability column (0–1) only blends volume, depth, and the number of wall residues. It is not a trained druggability score like fpocket or DoGSiteScorer: use it to order candidates, not to cite.
  • Use as docking grid box takes the centre and size of the selected pocket as the project's search box; Show pocket centres in the viewport draws numbered spheres. The list can be copied as Vina configuration parameters or exported as CSV.
  • Reference test: on 1HSG without MK1, the top pocket is centred 0.9 Å from the crystal ligand (volume ±207 Å³) and its wall holds the catalytic ASP 25.

Ligand access channels

Examines the routes a small molecule can take between the active site and the solvent. From a starting point — the grid box centre, or the centre of the pose being analysed — 64 rays are cast; along each ray the free gap to the nearest van der Waals surface is measured.

  • A ray that reaches solvent (a gap ≥ 6 Å after travelling ≥ 8 Å) without striking the protein is reported as a channel, with its bottleneck radius (the narrowest point), mean radius, length, the gatekeeper residues at the bottleneck, and the wall residues.
  • A rough guide: a bottleneck of ≥ 1.4 Å is wide enough for a small drug molecule to pass without side chains opening; 1.0–1.4 Å is narrow; below 1.0 Å it is effectively closed in that structure.
  • Draw the centreline in the viewport shows a string of spheres along the channel, with a red sphere marking the narrowest point.
  • A limit: straight paths only. A winding tunnel will not appear, and the length reported is a straight-line distance. For definitive channel analysis — gate motion over time included — use CAVER or MOLE on an MD trajectory.

Pose atom contact check

Counts every protein–ligand heavy atom pair within 4 Å in the pose being analysed, grouped by element combination (an RF-Score-style descriptor). Useful for weeding out poses whose docking score looks strong but which really only perch at the mouth of the pocket.

  • Per ligand atom is the most useful figure: below 1.5 contacts per heavy atom usually means the pose is dangling rather than buried.
  • The contact score uses simple linear weights. It is not a Random Forest model trained on PDBbind, and it does not replace a docking ΔG or MM/GBSA. A difference of a few kcal/mol against the docking score is ordinary, because the assumptions differ.

Kinetics and residence time

A rough estimate of the dissociation rate koff, the residence time τ = 1/koff, and the complex half-life. ΔG, the hydrogen bond count, and the hydrophobic contacts are filled in from the active pose and can be edited.

  • kon is guessed from the ligand's rotatable bond count; koff follows from Kd (that is, ΔG), then is slowed by buried hydrogen bonds and hydrophobic contacts.
  • A docking score does not model the transition state, so τ can be off by several orders of magnitude. Use it to compare ligands within one series; do not report it as a koff value. Real kinetic data come from SPR or BLI.

CYP450 metabolism sites

Flags the groups commonly oxidised by phase I cytochrome P450 (N-dealkylation, O-demethylation, benzylic, aliphatic, and aromatic hydroxylation, S-oxidation) together with suggested replacements, −OCH3 → −OCHF2 for instance. Detection uses SMARTS patterns, not a model trained on metabolite data or CYP isoform structures; the stability score is only a weighted count of susceptible groups, not an intrinsic clearance.

Fragment-based design (FBDD)

Two modes: Fragment growing grows bioisosteric groups onto a starting fragment, and Fragment linking joins two fragments with a choice of rigid or flexible linkers. For every derivative, MW, WLOGP, TPSA, QED, SAScore, and the Lipinski rules are computed at once. Import selected compounds adds them to the viewer as ligand objects; their 3D conformations come from a quick embedding, so go through Prepare ligands before docking them.

PROTAC designer

Assembles bivalent warhead – linker – E3 ligase binder molecules (VHL VH032, pomalidomide, thalidomide) with a choice of PEG, alkyl, or piperazine linkers. The warhead can be taken from a ligand in the project. The result is one covalently connected molecule, not a mixture of fragments, assessed against beyond Rule of 5 criteria: MW, LogP, TPSA, HBD/HBA, and rotatable bonds. The linker length shown is the theoretical fully extended chain span, not a distance from 3D modelling.

ADMET organ map

The Organ map tab in the ADMET prediction dialog condenses 30 ADMET-AI parameters into a two-row flow diagram. The top row follows the drug's journey: absorption (gut) → circulation (heart) → metabolism (liver) → excretion (kidney). The bottom row holds the organs and systems affected: brain, skin, cell nucleus, and overall exposure.

  • Each card scores 0–100 (higher is safer): the mean of its relevant endpoints, then capped by its worst endpoint, so one bad value cannot hide behind an average.
  • Click a card to see the endpoints behind it: the raw value, a 0–100 score bar, and which endpoints took no part in the score.
  • A blue number — on the brain card, for instance — is information rather than a risk judgement: crossing the blood–brain barrier is good for a neurological target and unwanted for a peripheral one, so VirmoLab does not decide that for you.
  • Organs with no model (lung, pancreas, thyroid) get no card and are named in the detail panel — no number is invented.
  • Motion: cards appear in sequence as the ligand changes, particles travel along the arrows at a speed following the predicted half-life, cards at risk pulse briefly, a card lifts when hovered, and a ripple spreads once when a card is selected. The Drug journey animation checkbox turns all of it off at once — useful on battery, or while recording the screen.
  • PNG/SVG export produces a still image, without animation, for a manuscript: it carries the ligand name and the colour legend, so the figure stands on its own in the text.
  • Keyboard: once a card has been clicked, left and right arrows move between cards in a row and up and down move between rows.

Every number here is a machine-learning prediction meant for triaging candidates, not a substitute for toxicity testing. If you also use a service such as pkCSM, treat the two as two different estimates rather than one truth.

Multi-parameter optimisation (MPO) and radar

Combines physicochemical properties, QED, SAScore, and the docking ΔG into one 0–100 suitability score with a radar chart that can be copied or saved as SVG. The Oral preset uses seven terms; the partial CNS-MPO preset uses four of the six terms from Wager et al. 2010 (MW, ClogP approximated by WLOGP, TPSA, HBD) — ClogD and pKa are not computed, so the figure is not comparable with Pfizer's 0–6 CNS-MPO value.

Virtual screening dashboard

For projects with many ligands: a ligand × parameter heat map, a ΔG against SAScore scatter plot coloured by MPO, a histogram of the affinity distribution, multi-criteria filters (Lipinski, Veber, PAINS, Brenk, GI absorption), a composite ranking, flagging of the top hits, and CSV export of the filtered results.

Matched molecular pairs (MMP)

Finds pairs of ligands that differ by a single R group (RDKit rdMMPA), then pairs that difference with the change in ΔG, QED, and SAScore. A pair with a large |ΔΔG| across very similar structures is flagged as an activity cliff — precisely where docking scores go wrong most often, so treat it as a pointer towards a substitution, not as a conclusion.

Glycosides and aglycones

Many natural products are glycosides, and a glycoside almost always scores more negatively than its aglycone simply because the molecule is larger. Analysis › Ligand properties and design › Glycosides and aglycones recognises cyclic sugar units on the project's ligands (pyranoses and furanoses joined through an O-, N-, or S-glycosidic bond), highlights them on the 2D diagram, then cuts them as enzymatic hydrolysis would: the linking heteroatom stays with the aglycone. C-glycosides such as vitexin and mangiferin are not cut.

  1. Click Add aglycone to project; any aglycone not already present is prepared and saved as a new ligand named “<glycoside> (aglycone)”.
  2. Dock that aglycone with the same receptor, box, and engine as its glycoside, then click Reload. A pair is only compared when both were docked under the same conditions.
  3. Read the Conclusion column: “Ahead because of size” means the glycoside does score more strongly, but each sugar atom contributes less than the ligand efficiency (LE) of its aglycone. Per-row detail appears below the table; Copy methods copies the methods paragraph together with its four references.

An example on HIV protease 1HSG (Vina, exhaustiveness 4, used as a workflow test rather than a biologically meaningful target): cosmosiin −8.75 against apigenin −7.82 kcal/mol, but LE 0.282 against 0.391; arbutin −6.60 against hydroquinone −4.56 kcal/mol, LE 0.347 against 0.570. Both are “ahead because of size”.

Pocket residue conservation

Analysis › Simulation and advanced research › Advanced research › Residue conservation. Paste FASTA homologues (or fetch them from UniProt, NCBI BLAST against Swiss-Prot, EBI, or RCSB; an online search sends the chain sequence off this computer), then click Compute & colour B-factor. The per-position percentage identity is computed on this computer (Needleman–Wunsch, BLOSUM62) and the protein is coloured by B-factor (100 = fully conserved). When a pose or ligand is selected in the Objects panel, the output also summarises the pocket residues (atoms within 5 Å of the ligand): how many there are, the mean pocket identity against the whole chain, and the least conserved pocket residues. Pocket residues that differ between homologues are where a selectivity argument starts; a fully conserved pocket means selectivity will be hard to achieve through it.

Multi-target selectivity

Compares the same ligand across several target projects: a ligand × target matrix, per-target z-score normalisation, the ΔΔG gap, and a profile classification (selective, semi-selective, promiscuous). The comparison only holds when every target was docked with the same engine, box size, and preparation protocol.

Protein–protein interfaces (PPI)

VirmoLab does not run protein–protein docking itself: for that, this tool prepares a PDB file you upload to ClusPro yourself under your own account — nothing is sent automatically.

Wet-lab assay plan

Interpreting docking results

Publication figure scripts

Docking protocol validation package (for publication)

Analysis › Validation and quality › Protocol validation package… (or the button in the Tests tab toolbar) is a standardised four-step wizard for validating a computational docking protocol before large-scale virtual screening:

  • Step 1 (Crystal redocking): tests whether the protocol reproduces the crystal pose (symmetry-corrected RMSD ≤ 2.0 Å). Option A uses your own project's redocking validation (its receptor, box, and engine); option B runs redocking from another complex PDB file. Where the crystal ligand has several copies, the largest single residue is used.
  • Step 2 (Cross-docking): needs at least 2 complex PDB files of the same target. Structures are superposed on their shared Cα atoms before RMSD is computed; a pair that cannot be aligned or fails to dock is marked grey as “failed” rather than filled in as zero.
  • Step 3 (Enrichment): uses the project's receptor and box. Actives come from ChEMBL (or your own CSV) with diverse scaffolds; decoys are drawn at random from approved drugs and natural products with matching physicochemical properties and a Tanimoto below 0.3 against every active, and every ligand is then genuinely docked. A ligand that fails to dock is excluded and reported, not counted as a score of 0. Output: ROC-AUC, BEDROC (α = 20), EF 1%, logAUC. A limit: these are not DUD-E decoys from ZINC; property matching does not remove topological differences, so treat the values as an upper estimate. Use at least 10 actives and 100 decoys for a defensible conclusion.
  • Step 4 (Summary & publication): metric cards for the tests that were actually run (the rest show “–”), the percentage of PoseBusters-valid poses from the QC already recorded on the project's docking results, a methods paragraph (in Indonesian and English) covering only the tests that were run, a one-page HTML report, and the ROC curve sent to the Figure composer.

Reverse targeting

Analysis › Multi-ligand screening › Reverse targeting & network… looks for the protein targets a single compound might act on:

  • The ligand route (ChEMBL, online): similar compounds in ChEMBL together with the targets they are active against (pChEMBL ≥ 6). Similarity is measured with the Tanimoto coefficient of Morgan fingerprints.
  • The structure route (target panel): docking against a panel of crystal structures validated by redocking, normalised as z-scores against random baits. This option is disabled when the installed package carries no panel.
  • Borda ranking: the ranks from both routes are summed; confidence is high when a target lands in the top 10 of both. A target that fails to dock gets no rank.
  • Every result is a computational hypothesis that has to be tested in the laboratory.

Networks & pathways

The Networks & pathways tab in the same dialog assembles the selected targets into a pharmacology network. Press Send selected targets to Network in the reverse targeting tab (the highlighted rows, or the high-confidence targets when nothing is highlighted), then Build network.

  • Pathway enrichment: a one-sided hypergeometric test against the Reactome or Gene Ontology (biological process) gene sets shipped with the package, with Benjamini–Hochberg correction. The background is every annotated gene in that file, and its size is stated in the methods paragraph.
  • Protein interactions (STRING): edges between targets with a combined score above a chosen threshold (0.4 / 0.7 / 0.9). A STRING score includes co-expression and text-mining evidence, not only physical interaction.
  • Disease associations (Open Targets): the top five diseases per target with an association score above a chosen threshold.
  • Sensitivity analysis: the network is rebuilt at STRING thresholds of 0.4/0.7/0.9 and with the top 5/10/20 targets. Genes that keep a high degree in at least 80 % of the combinations are marked as stable core nodes (drawn with a thick edge on the graph).
  • The graph zooms with the scroll wheel and pans by dragging. Results export as GraphML (for Cytoscape or Gephi), as a CSV edge list, or go to the Figure composer. Copy methods paragraph writes out the databases, versions, thresholds, sensitivity results, and the enrichment background.
  • Every network is a computational hypothesis that has to be tested in the laboratory.

QSAR & prediction models

Analysis › Multi-ligand screening › QSAR & prediction models… builds a model from your own activity data in five steps: Data → Curation → Model → Validation → Prediction.

  • Data: a ChEMBL activity table already fetched into the project, or a CSV file with smiles and nilai columns (in nM, µM, or M) or smiles and pIC50. Values marked > or < are skipped, because they are not exact measurements.
  • Curation: structures are standardised (largest fragment, neutralisation), inorganic compounds and fragments are discarded with the reason given, duplicate measurements are merged as a median, and then measurement ranges spanning more than 1 log and activity cliff pairs (Tanimoto similarity ≥ 0.85 with a difference ≥ 1.5 log) are flagged for you to decide on.
  • Model: regression or classification; Morgan2, MACCS, RDKit 2D descriptors, or a combination as features; Random Forest, SVR, kNN, Gaussian Process, or Ridge as the algorithm. Hyperparameters are tuned with 5-fold cross-validation inside the training set only.
  • Validation: two splits are reported side by side. A random split is almost always better than a Bemis–Murcko scaffold split; a large gap means the model only recognises scaffolds it has already seen, and the application writes that warning out. Also provided: Q², test-set R², the Golbraikh–Tropsha criteria, 50× Y-randomisation, a predicted-against-measured plot, a Williams plot, and permutation feature importance (with an example substructure for each Morgan bit).
  • Prediction: the project's ligands are predicted with a 90 % conformal interval and an applicability domain flag. Compounds inside the domain are listed at the top, those outside are dimmed below. If fewer than half the ligands fall inside the domain, VirmoLab states that the model does not fit that series: do not rank or select compounds from its predictions, but train a model on data with similar scaffolds instead. Results can be written into the predicted pIC50 column of the Results panel, exported to CSV, or the model saved along with a model card (holding a data fingerprint, the metrics, package versions, and the date).
  • A compound outside the domain still receives a number, but it is flagged and must not be read as a quantitative value.

Pharmacophore & 3D shape screening

Analysis › Multi-ligand screening › Pharmacophore & 3D shape screening… filters a compound library by 3D similarity to one reference ligand, ahead of the more expensive docking.

  • Query source: the pose currently open in the Interactions panel, or the project's co-crystallised ligand. Other project ligands are not offered, because their coordinates are only generated conformers rather than a bound pose. When the project has a receptor, protein heavy atoms within 4 Å of the reference ligand become exclusion spheres.
  • Features: hydrogen bond donors and acceptors, aromatic rings, and hydrophobic groups from the reference pose. Each feature can be switched off and its distance tolerance changed; the centre coordinates appear in the feature name's tooltip.
  • Scoring: each conformer of a compound is rigidly aligned to the reference ligand (shape and pharmacophoric colour), then the matching query features are counted on that aligned conformer. A slider sets the weight of the pharmacophore score against the shape-and-colour score.
  • Query validation: load actives for the target from ChEMBL or a CSV; matched decoys are generated automatically from a local library, then ROC-AUC, BEDROC, and EF 1% are computed for the query currently in force. EF 1% is only shown when the set holds at least 100 compounds. Changing a feature or a tolerance clears the previous validation figures, because they no longer apply.
  • Send top hits to docking adds the selected compounds as ligands in the main window and opens Prepare ligands, so protonation and PDBQT generation go through the usual route before docking.
  • Ligand-based screening is a coarse filter: in an internal test (a query from the 1HSG ligand against 8 HIV protease inhibitors and 520 matched drugs) the ROC-AUC was only 0.66. Use it to narrow a library, not as evidence of activity.

Hypothesis tracker → laboratory assays

The Hypothesis tab in the Wet-lab assay plan dialog compares in silico predictions against assay results you have measured.

  • Prediction to compare against: the docking ΔG, MM/GBSA from a finished MD simulation (the mean across replicas where there are several), or a pIC50 estimated from ΔG. An option with no data in the project is disabled.
  • Entering assay results: type the measured value and its unit into the table (pIC50 is computed for you), or press + Add entry for a compound not yet in the project — write its name exactly as the ligand's name so it pairs with its prediction.
  • Importing plate reader CSV: either a table of IC50 per ligand, or a matrix of 96-well plate readings. A matrix is a raw signal, not an IC50: VirmoLab normalises it against the blank and solvent control wells according to the plate layout currently open, then fits a four-parameter dose–response curve per compound. Build the plate layout first in the Microplate layout tab. An IC50 outside the concentration range tested is marked censored (“IC50 > 100 µM”, for instance) and left out of the correlation. The Z′ value of the solvent control against the positive control is reported too; Z′ < 0.5 means the assay window is too narrow.
  • Correlation: Spearman's ρ and Kendall's τ with bootstrap 95 % confidence intervals, and a warning when fewer than 8 pairs are available. The sign of the energies is inverted, so a positive correlation means the predicted ranking agrees with the measured pIC50.
  • Retrain QSAR with the new data opens the QSAR wizard with the project's lab activities already loaded, so a model can be retrained on your own measurements.

Relative binding free energy (experimental)

Analysis › Ligand properties and design › Relative free energy (experimental)… (shown in expert mode only) builds a perturbation network for a congeneric series. The method is far more accurate than a docking score, and far more expensive.

  • What Windows can do: choose compound pairs, map their atoms, build the perturbation network, see an estimate of the computational cost, and analyse the results.
  • Running the simulations: OpenFE runs only on Linux and macOS, so VirmoLab runs it inside WSL — as it does GNINA, Boltz-2, and Uni-Dock. Install it once with build_tools/pasang_openfe_unidock_wsl.sh (conda-forge packages, ±5 GB, not part of the installer). When OpenFE is absent the dialog says so plainly and can still build a network and load results produced on another machine. The Run button starts simulations that live on independently of the application: VirmoLab may be closed, and an interrupted calculation resumes because legs that already have results are skipped.
  • Protocol: the OpenFE default (11 λ windows, 5 ns, 3 repeats per leg) for numbers you intend to report, or a quick test (0.5 ns, 1 repeat) to confirm the workflow runs. Ligand partial charges come from OpenFF NAGL.
  • Installation test (16 October 2026, RTX 3060 Laptop): the lig_ejm_31 → lig_ejm_43 edge from the OpenFE TYK2 benchmark set with the quick-test protocol gave ΔΔG = +2.28 ± 0.95 kcal/mol against an experimental value of +1.28 kcal/mol (Ki 0.096 → 0.84 µM). The direction is right and the 1.0 kcal/mol difference still falls inside the statistical error of so short a protocol. The measured speed was about 99 ns/day for the complex leg, so the default protocol means roughly 1.7 days per complex leg per edge.
  • Pair selection: only pairs changing up to 10 heavy atoms are used. A larger perturbation is not merely slow, it is also untrustworthy.
  • The network: a minimum spanning tree picks the easiest perturbations, then edges are added to close cycles so consistency can be checked. The ΔΔG values around a closed cycle should sum to zero; a large deviation says the sampling is not yet adequate.
  • Cost: the number of edges multiplied by the lambda windows, the replicas, and the length of each window. The numbers are large: a dozen edges with the standard protocol is already hundreds of nanoseconds of simulation, which means days on a GPU.
  • This whole feature is labelled experimental and is only meaningful for a congeneric compound series.

Large library screening (active learning)

Analysis › Multi-ligand screening › Large library screening (active learning)… docks a small part of a library, trains a model on the scores obtained, then docks the compounds predicted to be strongest next. The design follows MolPAL (Graff et al., Chem Sci 2021).

  • What it is for: libraries of tens to hundreds of thousands of compounds that cannot all be docked. A small library, under a thousand compounds, is better docked outright.
  • The library: a SMILES/CSV/SDF file (.gz allowed), COCONUT natural products already downloaded, or the approved drugs that ship with the application. SMILES are checked by RDKit, salts and solvents are stripped (largest fragment), duplicates are removed, and 2048-bit atom-pair fingerprints are generated.
  • Round plan: a random initial batch, then several further rounds, each 1 % of the library by default. Model: an ensemble of three neural networks (the default) or a random forest; selection: UCB (prediction minus uncertainty), greedy, or random as a baseline.
  • The docking is ordinary docking: the engine settings, box, and receptor come from steps 3–4 and are then locked for the campaign, and each round enters the Queue panel as a job. Uni-Dock (GPU) helps a great deal here. Campaign ligands are tagged so they do not mix with the project's ordinary ligands.
  • It keeps running: a campaign continues with the dialog closed, is stored in the project, and resumes after the application is reopened. Stop after this round finishes the round in progress; Stop now cancels the jobs and returns the undocked ligands to the candidate pool.
  • What is reported: how many compounds have been docked, the best ΔG, the mean of the top 100, and the model's prospective accuracy (Spearman's ρ between the predictions and the docking scores of the last batch, computed before that batch was docked). The Predicted, not yet docked tab shows candidates predicted to be strong but not yet docked — predictions, not docking results.
  • How well it works (retrospective test): with the MolPAL Enamine docking scores (thymidylate kinase 4UNN) and only 6 % of the library docked, a neural network with greedy selection found 64 % of the best 1 % of compounds in a 10-thousand library and 74 % in a 50-thousand one; a random forest found 53 % and 57 %; random selection only 6 % and 5 %. Iterative screening therefore cuts the docking load more than tenfold while still missing some strong compounds: it is a filter, not a guarantee of finding the best.

Editing in the pocket (3D)

Analysis › Ligand properties and design › Edit in pocket (3D)… grows a group onto an existing pose and scores it in place, to answer the question “if I add a methyl here, does the score improve?”

  • How to use it: choose the parent pose, click an atom on the 2D diagram as the growth point, tick the groups you want to try, then click Score suggestions. The second tab replaces a whole functional group with its bioisostere (carboxylate → tetrazole, for instance).
  • How it works: analogues are built with the shared core pinned to the parent pose's coordinates, only the new group is optimised (MMFF94), then the pose is minimised in place and scored with AutoDock Vina --local_only. One suggestion takes seconds.
  • What is reported: the local ΔG, its difference from the parent pose (ΔΔG), the ligand efficiency, how many atoms clash with the protein before minimisation, and MW, logP, QED, and SAScore.
  • Its limits: a local score only ranks suggestions against the parent pose and does not replace redocking. The ligand conformation is effectively kept from the parent pose, so a suggestion that would really need a different binding mode will look bad. Add a promising suggestion to the project as a ligand and dock it again from scratch.

Generative design

Analysis › Ligand properties and design › Generative design… builds new analogues from one parent compound. Replacement fragments are taken from real compounds, so the suggestions tend to remain synthesisable, unlike a random structure generator.

  • Operations: replace fragment swaps a piece of the molecule for another that has appeared in a similar chemical environment; add fragment grows a new group. The context radius decides how wide an environment has to match: wider is more conservative and yields fewer results.
  • Fragment source: the database is built from the compound libraries already in VirmoLab, which means the approved drugs. Because that is a far smaller set than the whole of ChEMBL, its fragment diversity is narrower. Where the database came from is printed in the methods paragraph and the CSV export.
  • Filters: nuisance substructures (PAINS and Brenk), synthetic accessibility (SAScore), drug-likeness (QED), and novelty against the parent. How many were rejected and why is always shown, so you can tell when the filters are too strict.
  • Thresholds follow the parent: if your own parent compound already falls outside a threshold — a peptidomimetic inhibitor with a low QED, say — the threshold is lowered to match it. Without that, every derivative would be rejected and the feature would be useless on exactly the series that most needs optimising. This can be switched off.
  • Ranking: once candidates have been docked, they are ranked on a Pareto front over binding free energy, QED, and SAScore together, rather than one combined number. A candidate that fails to dock is removed from the ranking and counted separately, not given a substitute score.
  • Workflow: select candidates in the table, press Import selected as ligands, then carry on through Prepare ligands and the docking queue like any other ligand.
  • Every analogue is a computational suggestion. Whether it can actually be synthesised still needs a chemist's judgement before any laboratory work.

Electronic properties (xTB)

Analysis › Ligand properties and design › Electronic properties (xTB)… computes a ligand's electronic properties with GFN2-xTB. Docking judges shape and interactions; this part explains the electronic side — which atoms are open to attack, and how readily the molecule gives up or accepts an electron.

  • Descriptors: HOMO, LUMO, the gap, chemical hardness (η), chemical potential (μ), electrophilicity (ω), and the dipole moment. A solvent can be chosen (water, methanol, DMSO, and others) or the calculation run in the gas phase.
  • Fukui indices: f(−) marks atoms open to electrophilic attack, f(+) those open to nucleophilic attack. The values are coloured directly onto the atoms in the 3D viewer with a diverging scale and its numeric bounds.
  • Electrostatic potential: ESP points from xtb are mapped to the nearest atom for colouring. The numbers shown in the table still come straight from xtb, not from that mapping.
  • Relation to metabolism: the application compares the f(−) ranking against the predicted CYP metabolism sites. When both point at the same atom, the case for an oxidation site is stronger.
  • A limit that must be stated: GFN2-xTB is a semi-empirical method, not DFT. Its HOMO–LUMO gap tends to come out smaller than DFT's, so use it to compare trends between ligands rather than as an absolute value citable as a DFT result. This sentence is printed in the methods paragraph and the CSV export.

Peptide docking

Prepare › Step 2 · Ligands › Peptide from sequence… builds a peptide–receptor complex. Docking scoring functions such as Vina were designed for small molecules and become unreliable once a ligand has dozens of rotatable bonds, so this workflow uses no docking at all.

  • Input: a peptide sequence in one-letter code, up to 30 residues. A letter that is not an amino acid is highlighted red in place, so a typo shows at once. Non-standard codes such as X, B, or Z are accepted but warned about, because the prediction is less trustworthy.
  • Prerequisite: the same as co-folding, namely Boltz-2 installed in WSL. The receptor comes from the project, and the peptide is sent as a protein chain of its own.
  • Refinement: the predicted complex is minimised in implicit solvent with the receptor restrained, so it is mainly the peptide that adjusts. Short dynamics can be added, but take far longer. MM/GBSA is then computed with the peptide treated as the binding partner.
  • Results: the model's confidence, how far the peptide shifted during minimisation, the MM/GBSA estimate, the buried surface area, and a list of interface residues on both chains. The complex can be loaded into the viewer with the peptide in its own colour.
  • An MM/GBSA number is a rough estimate for comparing several peptides on the same target, not an absolute affinity prediction. The training-data leakage warning in the co-folding section applies here too.

Boltz-2 co-folding and pose agreement

The Co-folding tab in the Properties panel compares a docked pose against the complex structure predicted by the Boltz-2 AI model. Its purpose is a cross-check: two methods that work in entirely different ways, when they agree, lend the pose more confidence.

  • Prerequisite: Boltz-2 installed in WSL through build_tools/pasang_gnina_boltz_wsl.sh. The package and its model weights are MIT-licensed and are not bundled into the VirmoLab installer. Until it is installed the button stays disabled and the status explains how to install it.
  • How to use it: select one docked pose in the viewer, then press Run co-folding for this ligand. The prediction runs in the background; on a 6 GB GPU it often runs out of memory, and when it does, run it on the CPU.
  • Alignment: the Boltz-2 output structure is superposed onto the project receptor using Cα atoms before the ligand RMSD is computed. Without that step the two structures sit in different coordinate frames and the RMSD means nothing.
  • Agreement: Agree when the ligand RMSD is below 2.0 Å and both poses pass PoseBusters; Partial when the RMSD is small but a pose fails, or the RMSD is large while the contact pattern is still similar (IFP Tanimoto of at least 0.6); otherwise Conflicting. The Consensus scoring dialog shows the Boltz-2 affinity and the agreement as columns, and can be filtered to agreeing ligands only.
  • Agreement is not proof of correctness. Boltz-2 was trained on structures from the PDB. If your target and ligand are already in the PDB — 1HSG with indinavir, for instance — the model has most likely seen the answer during training, so high agreement proves nothing about its predictive ability. This is called training-data leakage. VirmoLab checks how similar your ligand is to ligands already in the PDB and warns when the similarity is high. A genuinely meaningful test uses a target or ligand not represented in the PDB.
  • A Boltz-2 affinity is a model estimate, not a measurement, and still needs laboratory testing.

Network pharmacology

This workflow answers a different question from docking. Docking asks how strongly one compound binds one protein; network pharmacology asks through which proteins and pathways a set of compounds might act on a disease. The shift is from one drug › one target › one disease to many compounds › many targets › many pathways.

Open it from the Network › Open the network pharmacology workflow… menu (Ctrl+Shift+J), or choose Network Pharmacology in the workflow selector of the Steps panel. The window has seven tabs worked through from left to right; their state is stored inside the project file, so the work can be left and resumed later.

1 · Compounds

Assemble a list of compounds with their SMILES. Three ways in: Medicinal plant compounds… (searching by plant taxon through LOTUS/Wikidata and COCONUT), Take project ligands (using the ligands already in this docking project), and Import CSV/TSV… for a list of your own — a KNApSAcK download with a SMILES column added from PubChem, for instance. The column separator and header names are recognised automatically; the SMILES column may be called SMILES, Isomeric SMILES, or Canonical SMILES. Where both are available, use isomeric SMILES because they carry stereochemistry, and do not mix the two kinds in one dataset: the target predictions stop being comparable.

Fill in the Compound source box with the plant or collection used. That text goes into the methods paragraph on the last tab.

2 · ADMET filtering

Of the hundreds of compounds in one plant, not all are worth carrying forward. This filtering works in two layers. The first is always available: the number of Lipinski rule-of-five violations and PAINS alerts, both computed by RDKit on your own computer. The second uses ADMET-AI predictions where it is installed — intestinal absorption (HIA), oral bioavailability, drug-induced liver injury risk (DILI), hERG inhibition, and Ames mutagenicity — and runs from the Predict ADMET (ADMET-AI)… button.

The default thresholds in the dialog are a customary starting point, not a fixed rule: adjust them to the size of your dataset and the aim of your study, then report the thresholds you actually used. A compound whose ADMET values are missing is not dropped for that reason — absence of data is not evidence of harm — but the reason is recorded in the Reason column so you know the filtering is incomplete. These results are predictions, not final truth.

3 · Compound targets

Two complementary target sources, which may be used together:

  • ChEMBL ligand similarity — finds structurally similar compounds (ECFP4 fingerprints) whose activity has been measured (pChEMBL ≥ 6), then takes the targets they bind. This gives the targets a compound might bind based on structural similarity, the same principle as SwissTargetPrediction.
  • CTD curated interactions — compound–gene relationships read and curated by curators from the toxicological and biomedical literature. This gives targets that have been reported, searched by compound name, so make sure the naming is standard.

If you would rather use the tools' own web pages, the Import target CSV… button accepts a table with a compound name column and a gene symbol column. For the structure-based route — docking compounds against a curated target panel — use Network › Reverse targeting.

4 · Disease genes & the intersection

Type a disease name, press Search Open Targets, choose the right entry from the list, then press Fetch disease genes. An Open Targets association score runs from 0 to 1 and blends genetic, literature, pathway, and drug evidence; the default threshold of 0.10 is lenient, so raise it when too many genes come back.

VirmoLab does not contact GeneCards automatically, because its licence is paid and forbids automated retrieval. If you have access, download the results yourself and use Import gene CSV…; DisGeNET, OMIM, and CTD exports are accepted too as long as there is a gene symbol column. Filter to protein coding on the source site first.

The intersection between compound targets and disease genes is what is called the potential therapeutic target, drawn as a Venn diagram on the right. The number in each region is a gene count; the circles are a fixed size rather than proportional, because a proportional Venn does not always have a geometric solution and a forced area is more misleading than a plain one.

5 · The PPI network

Protein–protein interaction edges come from STRING for the intersecting genes. The combined score is a confidence threshold: 0.40 medium, 0.70 high — the one network pharmacology papers customarily use — and 0.90 highest. Below 0.40, false positives are likely.

Keep in mind that a STRING edge does not always mean two proteins physically touch. STRING blends several evidence channels: experiments, curated databases (KEGG, Reactome, Biocarta), text mining across millions of abstracts, co-expression, gene neighbourhood, gene fusion, and co-occurrence. A functional association — two proteins working in the same pathway without ever touching — also produces an edge.

The network can be explored: the scroll wheel zooms, dragging pans, clicking a node highlights it with its neighbours, and double-clicking restores the full view. The table on the right ranks the hub proteins — those with the most connections, and therefore taken to matter most. The primary ordering uses MCC (Maximal Clique Centrality, the cytoHubba method), with degree, betweenness, and closeness alongside for comparison. Selecting a row in the table highlights its node in the picture.

Do not read a network as merely a scatter of dots and lines. What you are after is the hub proteins and the strength of their evidence, not how the network looks. For further analysis, Export GraphML opens this network in Cytoscape or Gephi.

6 · Pathways

Pathway enrichment uses a one-sided hypergeometric test: how unlikely it is that this many of your genes land on one pathway by chance alone. Because thousands of pathways are tested at once, the p value is corrected by the Benjamini–Hochberg method into a q value; use q, not p, to decide which pathways to report. Two gene sets are available offline: Reactome and Gene Ontology Biological Process. The background is every gene in the chosen set.

7 · Figures

Five publication-ready images are assembled from the workflow's state, chosen in the list on the left and shown at once in the preview on the right. Number of items sets how many hub proteins or pathways are drawn; DPI applies to raster output only.

  • Intersection Venn diagram — compound targets against disease genes.
  • Layered network — compounds, targets, pathways, and disease in one force-directed picture.
  • Circular hubs — the most central proteins arranged in a circle, coloured by MCC rank. A circular arrangement is used because what is being read is the ranking and the density of connections between hubs; a force-directed layout hides that ranking. This is the open equivalent of the cytoHubba figure that network pharmacology manuscripts customarily use.
  • Pathway bubble plot — the standard form for pathway enrichment: gene ratio on the x axis (query genes landing on the pathway divided by all query genes), point size as the gene count, colour as −log₁₀(q). The numbers are written beside each point, so the figure still reads when printed in black and white.
  • Pathway bars — the most compact form, gene count per pathway.

Ordered quantities (hub rank, q value) are drawn with a single hue running light to dark rather than a rainbow, and the ramp has been checked for colour-blind legibility and contrast against the background. That means the figure still reads correctly in greyscale: darker always means higher.

Save SVG/PNG… writes the figure currently shown; Save all… writes every figure whose data exist into one folder, each as both SVG and PNG. Use SVG where the journal accepts vector — the files are small and never pixelate when enlarged.

8 · Report

Summary cards show the figures from each stage, and below them the full report is reassembled every time a stage completes — nothing needs pressing. It has ten sections: summary, methods, compound list, filtering results with the reason for each exclusion, targets per compound, disease genes and their intersection, network topology with the hub protein table, pathway table, Limitations, and a table of data sources with their versions and licences.

The report can be saved as PDF, Word, or HTML. Export JSON… saves the entire workflow state for a supplementary file, and the copy button gives the methods paragraph alone, in Indonesian or English.

The statistics included

Two things are tested with the same statistics engine as the Tests & Plots tab, so test selection and assumption checking stay consistent.

  • Properties of compounds that passed against those excluded — molecular weight, WLOGP, TPSA, QED, and SA Score are compared between the two groups. The test is chosen automatically: Welch when the distribution is normal by Shapiro–Wilk, Mann–Whitney when it is not. This answers a question a reader will fairly ask: what did the ADMET filtering actually remove? If not one property differs meaningfully, the filtering worked through predicted toxicity criteria rather than through molecular size or lipophilicity — and the report states that conclusion as it stands.
  • Network topology — density, degree distribution (mean, SD, median, maximum), clustering coefficient, the number of connected components, and the number of isolated proteins, with a paragraph reading them. When the highest degree far exceeds the median, the report names that pattern: a few proteins hold most of the connections, which is characteristic of biological networks.

The Limitations section is always printed and cannot be removed. It covers six things: the dependence on how complete the public databases are, dose not being accounted for, digestion and metabolism being ignored, the direction of interactions being unknown, time and location in the body being ignored, and the fact that a STRING edge is not only a physical interaction.

Carrying on to docking

The button in the bottom right follows whichever stage is open: while the workflow is unfinished it reads Next: <the following stage> and stays disabled until the current stage has content. On the Report tab it becomes Take to molecular docking….

That button selects only the compounds that passed filtering and hit one of the top ten hub targets, then opens the import dialog with their SMILES already filled in and moves the Steps panel to the Molecular Docking workflow. This is where 3D structures are first built — not at the beginning — because by this point it is clear which compounds are worth testing and against which protein. After docking, MD & MM/GBSA is there when the stability of a pose needs checking.

Command line (VirmoLab-cli)

VirmoLab-cli.exe sits in the VirmoLab installation folder. Open a Command Prompt there (or write the full path), then for example:

VirmoLab-cli dock -r 1HSG -l kandidat.smi --acuan auto -o hasil_1hsg
VirmoLab-cli dock -r AF-P00918 -l folder_ligan --kantong 1 --mesin vina -o hasil_ca2
VirmoLab-cli reseptor 1HSG -o rec.pdbqt --flex A:25,B:25
VirmoLab-cli dock -r 6OIM -l sotorasib.smi --acuan auto --kovalen A:12 -o hasil_kovalen
VirmoLab-cli info
  • Commands: info, uji (self-test), reseptor (receptor), ligan (ligands), kantong (pocket, P2Rank), alphafold, dock, mmgbsa. The command names stay Indonesian so that scripts keep working in either interface language. Add -h for every option.
  • mmgbsa -r hasil_dock -o folder [--md --ns 2 --pelarut implisit|eksplisit]: MM/GBSA of the best poses from a dock output folder (or -r a PDB file or code plus -l an SDF pose) → mmgbsa.csv.
  • dock accepts a receptor as a PDB code, AF-<UniProt>, a PDB/CIF file, or a ready PDBQT; and ligands as a file, a folder, or SMILES text. The docking area: --pusat X Y Z (plus --ukuran), --acuan file or --acuan auto (the native ligand), or --kantong N.
  • Output: a pose folder (DLG/PDBQT plus an SDF of the best poses), ringkasan.csv (ΔG, Ki, LE, hydrogen bonds, hydrophobic contacts, contact residues), metode.txt (the parameters plus a command that reproduces the run exactly), and log.txt. An exit code of 0 means at least one ligand succeeded.

Projects, autosave, recovery

  • A project is a Name.vmd folder holding proyek.json, the receptor, ligands, grid, and results (the engines' own logs are always kept). It is created automatically at the first preparation step; manage it through File › New project / Open project / Open recent project / Save project (Ctrl+S).
  • Autosave runs after every significant change and every 3 minutes, keeping the last 5 backups in .cadangan.
  • If VirmoLab closes abnormally — a power cut, say — the next start offers to Recover the last session.
  • Tools › Open project folder opens the active project folder in Explorer.

Privacy and internet connections

VirmoLab sends your projects, structures, and results nowhere, and carries no telemetry. Project files, logs, and settings stay on your own computer (Documents\VirmoLab, %LOCALAPPDATA%\VirmoLab, HKCU\Software\VirmoLab; the portable build keeps everything inside its own folder).

The only things that contact the internet are:

  • Downloads you ask for yourself: RCSB PDB, AlphaFold DB, PubChem, ChEMBL, COCONUT, LOTUS, STRING, Open Targets. All that is sent is the code or search term you typed.
  • The ColabFold MSA server for Boltz-2 — only when Request MSA from ColabFold is ticked; the protein sequence in question is sent with the request. Without it, Boltz runs single-sequence and entirely locally.
  • The update check: one GET request to api.github.com at most once a day, reading only the latest release number. Turn it off under Tools › Settings if you would rather it did not. A new installer file is downloaded from GitHub only when you yourself press Download and install in the update dialog; all that is sent is the request for that release file.
  • The advanced tool installer (WSL): package downloads from conda-forge, GitHub, PyPI, PyTorch, and Hugging Face, only while you are pressing Install.

The structures and ligands you open are never sent along with an update check or a tool installation.
